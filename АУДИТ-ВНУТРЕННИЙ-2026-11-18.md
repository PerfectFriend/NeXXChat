# NeXX — внутренний аудит 2026-11-18 (свежий, после закрытия внешнего аудита)

База: `cargo test --release --lib` → 104/104, clippy 0, interop-all 13/13 PASS (c7df20c),
ветка master, .git pack 61.5 МБ.

## 1. Что подтверждено работает (проверено сейчас)

- Ядро `rustcore`: 11 725 строк, 104 unit, 13 живых интеропов vs публичной сети SimpleX.
- JNI-граница: 31 экспорт под `ffi_guard!`, opaque seed-handles, Zeroizing.
- TLS-пиннинг обязателен (K1/C1), 7 негативных тестов пиннинга зелёные.
- XFTP: chunked до 8 МБ против xftp1, whole-file SHA, FDEL, лимит 512 МБ в UI.
- Локальный SOCKS5 + upstream через Xray/libv2ray (тест chain), kill-switch, лимит 256 соед.
- Шифрованные локальные сторы (контакты/очереди/сообщения/группы), idle-reaper сессий.
- `.so` вне git в `app/src/main/jniLibs` (проверено `git ls-files` — только assets).

## 2. Находки этого аудита

### Broken
- Нет. Регрессий не обнаружено.

### Dead / частично мёртвое
| ID | Что | Факт |
|---|---|---|
| D1 | `app/libs/libv2ray.aar` (60 МБ) всё ещё в git | `git ls-files` подтверждает; pack 61.5 МБ — остаток M5 не закрыт |
| D2 | Один SMP-релей за раз | `chat_host/chat_port` — одна строка; multi-server fan-out (ядро «тумана») не реализован |
| D3 | `.onion` недоступен | нет Tor-транспорта в ядре (arti не подключён); своя нода в онионе не коннектится |
| D4 | route_decision = только allow/block | нет benchmark/рейтинга outbound'ов; «автовыбор быстрой ноды» не существует |
| D5 | Свой релей в UI невозможен | `servers.rs` — только smp6; неизвестный хост отклоняется (M6) — для своего облака нужен UI ввода |
| D6 | Нет desktop-бинаря | `app-rust` = cdylib + android_main только; нетбук не запустит |
| D7 | Импорт wg/vless-конфига в UI есть, но нативного WG-транспорта нет | только через Xray outbound |

### Unbuilt (осознанно)
- PQ ratchet / XRCP — ждём стабилизации simplexmq.
- Push-уведомления (сейчас poll).
- Экспорт/импорт полного профиля (сид есть, но нет «перенос профиля целиком» с контактами+историей одной ссылкой).
- File-версионирование и TTL-ссылки на XFTP-хранилище.
- Safety numbers / верификация контактов.

## 3. Идеи (по убыванию ценности для твоего сценария «облако нод в тумане»)

1. **arti in-process Tor** ( без Orbot): dial `.onion` через `TorClient::connect`; несколько `isolated_client` = разные circuits → multi-path.
2. **Multi-SMP fan-out**: клиент держит N серверов (твои ноды + публичные как decoy), сообщение дублируется на все, дедуп по msgId — «каждый пакет своим маршрутом» на уровне протокола SimpleX.
3. **Benchmark + рейтинг маршрутов**: per-outbound latency (TCP+TLS handshake) + throughput (XFTP FGET маленького chunk'а); route_decision выбирает лучший, fallback при деградации; UI-отчёт рейтинга.
4. **UI своего релея**: ввод `.onion:port` + keyHash (обязателен по K1) + имя; хранение в шифрованном сторе; список нескольких релеев с чекбоксами fan-out.
5. **Desktop-бинарь** (`src/bin/desktop.rs` на eframe) — тот же rustcore на нетбуке.
6. **Чистка git от aar**: `git filter-repo` (или замена на внешнюю поставку `libv2ray.aar` через скрипт скачивания + sha256, как LIBV2RAY.sha256) — pack 61.5 МБ → ~1 МБ.
7. **Нативный WireGuard** (wireguard-rs / boringtun) как transport рядом с Xray — чтобы wg-конфиги работали без libv2ray.
8. **XFTP-хранилище «важных файлов»**: квота на ноду, file-версии (fileNonce+индекс), ссылки с TTL/паролем, авто-репликация на 2+ ноды облака.
9. **Реестр нод облака**: список нод как contact-link'ов, gossip статуса через SMP (кто онлайн, load), UI-«карта тумана».
10. **Перенос профиля одной ссылкой** (зашифрованный bundle: сид+контакты+история, по QR/nexx://), для миграции между устройствами.

## 4. Рекомендуемый порядок

D3+D5 (arti + свой релей) → D2 (fan-out) → D4 (benchmark) → D6 (desktop) → D1 (чистка git) → 8/9/10 по мере надобности. PQ — когда выйдет в simplexmq.
