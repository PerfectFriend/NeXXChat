## 0. Правило, по которому теперь оценивается проект

## 1. Что закрыто (проверяйте в первую очередь)

### C1 — MITM / аутентификация сервера ✅
- `rustcore/src/protocols/smp_client.rs`:
  - `validate_server_chain(leaf, chain, expected_key_hash)` — настоящая проверка:
    CA ищется по **строгому** совпадению SHA-256, leaf проверяется через
    `X509Store`/`X509StoreContext` (подпись), `any-match` и CN-fallback **удалены**.
  - `ct_eq()` — constant-time сравнение хешей.
  - keyHash **обязателен**: `smpConnect(host, port, caPem, keyHashHex, …)`;
    пустой CA PEM или keyHash → ошибка, не «пропустить проверку».
  - SMP-hello leaf обязан совпадать с TLS-leaf (`smp_handshake`).
  - **Channel binding**: `session_id` из server hello обязан совпасть с собственным
    TLS Finished (`own_finished()`; в модели SimpleX server hello несёт
    `tlsUnique` клиента — сверено с `simplexmq/Transport.hs`, `getFinished`).
    Проверено побайтово против `smp6.simplex.im:5223`.
- **Негативные тесты**: `rustcore/tests/audit_c1_pinning.rs` — 6 сценариев
  приёмочной таблицы аудита + тест constant-time. Команда:
  `cargo test --release --test audit_c1_pinning`.

### C2 — секреты в тексте ошибки ✅
Диагностический блок вырезан, ошибка — статическая строка.
Приёмка: `strings libnexxrust.so | grep -cE "secret=|sessId=|WORKS="` → **0**
(проверено также для `.so` внутри APK).

### H1 — частичное чтение блока ✅
`SmpClient.read_buf` + `TlsIo::read_some`: таймаут посередине блока больше не теряет
принятые байты. Таймауты разделены: poll 300 мс, команды 10 с.

### H2 — глобальный Mutex на сеть ✅
`SESSIONS: HashMap<i64, Arc<Mutex<Session>>>`; глобальный лок только на карте.

### H3 — паники через FFI ✅
Макрос `ffi_guard!` (`catch_unwind`) на всех JNI-экспортах, poison-безопасные локи,
`connreq.rs`: `hosts.remove(0)` → `hosts.get(0).ok_or(…)`.

### H4 — потеря сообщений / DoS ✅
`smpPoll`: битое сообщение не рвёт цикл — ACK + счётчик `damaged` в JSON-ответе.

### H5 — ключи очередей ✅
Новый `rustcore/src/protocols/queue_store.rs`: индекс очереди
`m/0'/0'/{i}'` + `m/0'/1'/{i}'` (уникально), шифрованное (AES-256-GCM) хранилище
реквизитов, `DEL` на сервере при закрытии очереди.

### H8 — Debug/логи ✅
`XKey`: `Zeroize` + `ZeroizeOnDrop`, кастомный `Debug` → `<redacted>`.

### M1/M2/M4/M5 ✅ (частично для M4/M5)
`serde_json` для JSON; `connect_timeout` 15 с; манифест: `allowBackup=false`,
`dataExtractionRules` (бэкап исключён), `usesCleartextTraffic=false`;
`remap-path-prefix` + скриптовая чистка путей → `strings .so | grep -c /home/thomas` → 0.

## 2. Честно не закрыто (проверьте, не верьте на слово)

- **H6 (частично)**: единая BIP39-функция (SHA-512/2048) + NFKD есть; но JNI ещё
  принимает произвольные `iterations`/`dkLen` — это в следующем спринте.
- **H7 (частично)**: `Zeroize` есть; но сид всё ещё ходит через JNI как `String` —
  opaque-handle API не сделан.
- **M3**: reconnect/backoff в UI-воркере не сделан.
- **M6**: CA-цепочка всё ещё hardcoded-константа в `app-rust/src/ui.rs` (нужен конфиг серверов).
- **M7–M11**: не начаты (KDF-обёртка хранилища, лимиты параметров, split crates,
  BIP-32 edge cases, дубли `hex_decode`).
- **PQ ratchet, XRCP, группы, multi-hop, chunk-XFTP** — не реализованы (unbuilt).

```bash
cd rustcore
cargo test --release --lib                      # 76/76
cargo test --release --test audit_c1_pinning    # 7/7 (негативные C1)
bash scripts/interop-all.sh smp6.simplex.im:5223   # 5/5 PASS
strings target/release/libnexxrust.so | grep -cE "secret=|sessId=|WORKS="   # 0
strings target/release/libnexxrust.so | grep -c "/home/thomas"             # 0
```

Интероп-прогоны: `chat_flow`, `agent_smoke`, `agent_rotate`, `smp_cmds`,
`invite_flow` — все против публичного релея `smp6.simplex.im:5223`.
Требуется `NEXX_TLS=openssl` (Ed448 в ClientHello; ring ed448 не умеет) и
CA-цепочка `rustcore/assets/smp6-5223-chain.pem` (в репозитории) либо своя:
`openssl s_client -connect smp6.simplex.im:5223 -showcerts </dev/null | awk '/BEGIN CERT/,/END CERT/'`.

## 4. Зоны повышенного внимания

- `rustcore/src/jni_smp.rs` — граница JNI: ключи из keytree, без хардкода.
- `rustcore/src/protocols/smp_client.rs` — TLS-бэкенды, пиннинг, channel binding.
- `rustcore/src/protocols/queue_store.rs` — новое: шифрованное хранилище очередей.
- `rustcore/src/keytree.rs` — деривация, `Zeroize`.
- `rustcore/src/protocols/smp.rs` — ручная реконструкция crypto, закрыта KAT.
- `rustcore/src/protocols/connreq.rs` — connReqData по spec, URI `nexx://link#/<b64url>`.

которые подтверждены кодом, тестом или воспроизводимым прогоном. Всё, что вы
сочтёте недоказанным, — помечайте как «не проверено», а не как «✅».
